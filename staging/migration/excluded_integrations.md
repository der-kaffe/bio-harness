# Excluded integrations

## job-forge / Geometra

The current global config is generated by `@agent-pattern-labs/iso-route` inside job-forge 2.14.50. It supplies model defaults, obsolete inline profiles, the Geometra MCP launcher, and project trust entries. The package postinstall deliberately symlinked the consumer's `.codex/config.toml`; because the consumer path was the home directory, it became global configuration.

Geometra provides a specialized MCP/browser capability through:

```text
npx --no-install job-forge mcp:geometra
```

It is excluded from the candidate core because:

- a specialized job-search/browser integration should not own global Codex defaults;
- the symlink depends on a mutable/collectable npx cache;
- legacy profile tables are incompatible with current Codex profiles;
- recent npm resolution attempts failed, so enabled configuration is not proof of a healthy server;
- inclusion would violate the staging requirement not to change or assume real MCP integrations.

Nothing is uninstalled or disabled in the real home.

## Future independent reintroduction

Before reintroducing it:

1. Confirm a maintained, resolvable package/version and supported launcher.
2. Choose a stable installation location independent of the global config file.
3. Inspect postinstall/sync behavior and prevent it from taking ownership of `~/.codex`.
4. Test the MCP in an isolated `CODEX_HOME` without real credentials where possible.
5. Define required tools, approval behavior, browser mode, data exposure, and rollback.
6. Add only the MCP stanza to user or appropriate project config after human approval.

Do not restore the npx-cache config symlink as the integration mechanism.
